# 디자인 레퍼런스

픽셀 아트 생성기(사진·그림 → 픽셀 아트 → 스프라이트 시트)를 만들 때 참고할 레퍼런스 모음이다.
2026-10-28에 웹 검색으로 모았다. 검색 결과는 대부분 2차 자료(소개·비교 글)라서,
실제 화면 구성과 조작감은 각 사이트나 앱에서 직접 확인해야 한다.

## 1. 변환 화면 (사진 → 픽셀)

| 레퍼런스                                                                                                            | 참고할 점                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Image to Pixel Art 변환기 (artincontext)](https://artincontext.org/image-to-pixel-art/)                            | 지금 프로젝트와 가장 비슷한 구성. 가로 폭 슬라이더(16~256), 색 수 자동 선택과 레트로 팔레트(PICO-8, Game Boy, NES), 디더링, 밝기·대비·채도 조절, 드래그 구분선 비포/애프터가 있다. 픽셀마다 선을 긋고 10칸마다 굵은 선을 넣는 **격자(Grid) 보기**가 있고, 이미지를 서버에 올리지 않고 브라우저 안에서 처리한다고 안내한다. |
| [ComfyUI PixelArt Detector](https://runcomfy.com/comfyui-nodes/ComfyUI-PixelArt-Detector/PixelArtDetectorConverter) | 디더링 옵션이 none, Floyd-Steinberg, Bayer 2~16으로 나뉜다. 팔레트에 맞지 않는 잡색을 지우는 정리 토글이 있어 우리 "외톨이 정리"와 같은 개념이다.                                                                                                                                                                          |
| [Pic To Pixel (GitHub)](https://github.com/Leodotpy/PicToPixel)                                                     | 비포/애프터 예시 섹션이 있어 두 그림을 나란히 놓는 배치를 참고할 수 있다.                                                                                                                                                                                                                                                  |

### 디더링 관련 메모

- 순서 디더링(Bayer)은 규칙적인 무늬가 생겨서 움직이는 스프라이트에서는 어색할 수 있다는 의견이 있다.
- Floyd-Steinberg는 품질과 계산 비용의 균형 때문에 흔히 기본값으로 쓰인다는 의견이 있다.
- 그래서 "없음 / 순서(Bayer) / 오차 확산(Floyd-Steinberg)" 세 가지를 모두 제공하고, 기본값은 용도에 맞게 정하는 구성이 무난하다. 현재 우리 기본값은 "없음"이다.

## 2. 편집과 애니메이션 화면 (레이어·타임라인·스프라이트 시트)

| 레퍼런스                                                                          | 참고할 점                                                                                                                                   |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| [Piskel](https://best-of-web.builder.io/library/piskelapp/piskel)                 | 브라우저에서 동작하는 가장 가까운 레퍼런스. 프레임 타임라인, 실시간 애니메이션 미리보기, 양파껍질(onion skin), 레이어를 지원한다.           |
| [Aseprite](https://best-of-web.builder.io/library/aseprite/aseprite)              | 레이어와 프레임을 분리하는 모델, 실시간 미리보기, 양파껍질, 레이어 그룹, 스프라이트 시트·GIF·PNG 시퀀스 내보내기. 기능의 기준선으로 삼는다. |
| [Pixelorama](https://best-of-web.builder.io/library/Orama-Interactive/Pixelorama) | 양파껍질, 셀 연결(cel linking), 프레임 태그와 그룹, 스프라이트 시트 가져오기.                                                               |

### 공통 구조

- **레이어 × 프레임 격자**: 한 칸(셀)이 한 레이어의 한 프레임이다.
- 프레임 타임라인, 양파껍질, 실시간 미리보기는 세 도구가 모두 갖고 있다.
- 프레임 태그(예: "걷기", "점프")로 애니메이션을 구분한다.

## 4. 이 프로젝트에 적용할 점

1. 결과 수정 화면에 **격자 보기 토글**(10칸마다 굵은 선)을 넣는다. 칸 수를 세기 쉬워진다.
2. Day 2의 레이어·애니메이션 화면은 **레이어 × 프레임 격자와 타임라인** 구조로 설계한다.
3. 한글 UI 폰트는 Galmuri로 통일하고, 색은 어두운 남색 바탕에 포인트 색 1~2개로 제한한다.
4. "이미지는 서버로 올라가지 않아요" 안내 문구를 화면에 넣어 브라우저 처리 방식을 알린다.

## 5. 검색에서 찾지 못한 것

- Dribbble, Behance의 개별 작업물은 검색에 잡히지 않았다. "pixel art editor UI", "sprite editor UI" 같은 키워드로 직접 찾아봐야 한다.
- 일부 검색 결과(peoplespharmacy, geosirius 미러 등)는 스팸성 페이지로 보여 제외했다.
- 위 표의 Piskel, Aseprite, Pixelorama 링크는 소개 페이지이고, 패널 배치나 시각 디자인을 자세히 설명하지 않는다. 앱을 직접 열어 확인해야 한다.
